# 项目维护与方向基线

本文用于防止新任务、旧分支或历史说明把项目带回已经废弃的方向。它记录稳定决策与目录职责，不记录密码、实时服务器地址、制品哈希或一次性故障现场。

## 1. 新任务的上下文链

Codex 进入仓库后按以下顺序建立事实：

1. 全局与项目级 `AGENTS.md`：工作边界、数据安全和验收要求；
2. `README.md`：当前可用能力、版本和开发入口；
3. `docs/PRD.md`：产品与数据语义；
4. 本文：当前方向与已废弃方向的边界；
5. `docs/REAL_LEDGER_FINDINGS_2026-08-09.md`：真实账本样本所支持的结论；
6. 当前代码、测试、Git 状态与实时 API：最终运行事实。

聊天记录、旧交接文件、归档 APK、旧分支和历史服务器笔记只能用于追溯，不得覆盖以上当前事实。

## 2. 当前方向与已废弃方向

| 主题 | 当前契约 | 不得静默恢复的旧方向 |
|---|---|---|
| 顶层交易 | 一笔顶层交易代表一次独立付款；不同日期、订单或付款行为必须拆分 | 一段输入永远只生成一条记录 |
| 商品折叠 | 按同一次结账或同一订单折叠，超市品牌只是识别证据 | 只有盒马折叠，其他来源一律平铺 |
| 父账单 | 父级是结算容器，保留实付；分类以商品明细为真值 | 让模型随意给混合父账单选择一个主分类 |
| 数据维度 | 不保存支付方式；商户只做搜索筛选；标签最多一个可选场景值 | 支付方式、商户、分类和多个模型标签混为一组属性 |
| 语音 | 应用采集麦克风并调用 `mimo-v2.5-asr`，转写后仍需编辑和解析确认 | 把输入法听写称为应用内语音，或转写后自动入账 |
| 保存交互 | 成功后留在录入页并重新聚焦；明细页由用户显式进入 | 延迟后自动跳转明细，打断连续记账 |
| 账本安全 | 批量原子写入，验证 LocalStorage→JSON→读回和 checksum | 只验证解析结果或页面渲染就宣称账本安全 |
| 云同步 | 默认关闭、本地优先、单设备账号；冲突先合并并保留本机 | 把云端当主账本、静默覆盖，或宣称已支持完整多端同步 |
| 交付边界 | 客户端改动只交付 APK；只有 API/数据库/运行配置改变才部署服务端 | 把“在线测试”理解为必须部署公网 Web，或无关地重建服务器 |

这些变化中，结算分组、数据维度、连续记账和单设备云同步是用户明确确认后的产品收敛；它们不是临时实验。

## 3. 当前仍需显式说明的边界

- 客户端候选版与服务端版本可以不同。当前 README 会明确客户端 RC 与兼容的 API 基线；不要仅凭版本号不同判断漏部署。
- GitHub 分发的仍是 debug APK / Pre-release，不等于应用商店稳定版。
- `scripts/verify-feature-contracts.mjs` 主要检查源码契约；存储、折叠分类和统计另有行为测试。关键 UI 仍需要窄屏真实浏览器点击，不能把源码正则检查当成完整 E2E。
- 账号的日/月额度在服务端仍是整数，没有原生 `unlimited` 类型；管理员可设为整数上限，但全站分钟级防滥用限流仍独立存在。
- 已合入 `main` 的旧功能分支只保留历史意义。新任务不得因为分支名较新而绕开当前 `main`。

## 4. 根目录与本地文件

根目录保留工具默认发现或项目入口所需的文件：`package*.json`、`index.html`、`tsconfig.json`、`vite.config.ts`、`capacitor.config.ts`、`eslint.config.js`、`.env.production`、许可证与主文档。为追求表面整齐而移动这些入口，会增加隐式参数和编辑器漂移。

目录职责：

```text
config/                 可显式寻址的二级构建配置
docs/                   产品、维护、安装和真实数据结论
scripts/                可重复的检查、测试与打包入口
src/                    客户端源码
server/                 API、数据库模型与服务端测试
android/                Capacitor Android 工程
.local/                 不纳入 Git 的本机私有输入和制品
  credentials/          MiMo 本地测试密钥
  signing/              Android 升级签名输入
  releases/             本地构建的 APK
  archive/              历史制品、日志、真实账本证据和旧说明
  toolchain/            任务产生的本地辅助运行库
```

`.local/` 不随 Git 克隆或同步。签名文件和需要保留的真实账本证据必须另有可靠备份；整理根目录不得删除或覆盖它们。

## 5. 维护门禁

- 进入项目先确认分支、HEAD、远端与工作区，再读取上述上下文链。
- 同类错误再次出现时，优先补 doctor、脚本或行为回归，而不是只写聊天提醒。
- 语义改动运行 `npm run verify`；Android 改动运行 `npm run android:build`；服务端改动另跑服务端构建与测试。
- 发布前在最终提交上验证制品元数据、录音权限、签名连续性和哈希；手机验收仍由用户独立完成。
