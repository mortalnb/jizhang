# 智能记账 PRD

## 1. 文档信息

- 产品名称：智能记账
- 当前版本：v1.4.3
- 产品形态：Android 本地优先记账工具
- 发布方式：GitHub 开源发布，用户自行下载 APK，可自行配置模型接口，或联系作者申请内测账号体验云端模型代理
- 文档类型：产品需求文档
- 文档状态：当前版本需求基线

## 2. 项目背景

个人日常消费记录中，超市、生鲜电商、淘宝/天猫等订单经常包含多个商品。传统记账方式通常只能记录一笔总额，无法自然保留商品级明细，也难以做准确的分类统计。

本项目希望利用多模态大模型和本地数据管理能力，让用户可以通过自然语言或账单截图快速生成可核对的本地账单。项目当前采用开源工具路线，用户可以自行配置模型 API Key 和模型服务；小范围内测用户也可以联系作者申请云端模型代理账号。

## 3. 项目目标

### 3.1 核心目标

- 降低个人记账录入成本。
- 支持从自然语言和订单截图中提取结构化账单。
- 对盒马等多商品订单保留商品级明细。
- 保持本地优先的数据保存方式。
- 允许用户自行配置视觉模型接口。
- 提供预算、分类、标签和消费洞察能力。

### 3.2 非目标

- 不提供公开注册的云端账号体系。
- 不提供多端同步。
- 不在 App 中暴露商业模型 Key。
- 不承诺识别结果完全准确。
- 不提供财务、投资、税务或消费决策建议。
- 当前不以应用商店正式上架为主要目标。

## 4. 目标用户

### 4.1 主要用户

- 愿意自行配置模型 API Key 的个人用户。
- 想联系作者申请内测账号体验云端模型代理的用户。
- 有较多线上订单、超市订单、生鲜订单的记账用户。
- 希望账单数据默认保存在本机的用户。
- 对 AI 工具、开源项目或自托管模型有一定了解的用户。

### 4.2 次要用户

- 想研究 AI 记账产品形态的开发者。
- 想基于 React + Capacitor 开发 Android 工具应用的人。
- 想复用订单截图识别和本地记账思路的人。

### 4.3 不适合的用户

- 不愿意配置 API Key、也没有内测账号的普通用户。
- 需要云同步、账号体系、多端访问的人。
- 希望账单完全自动保存且不核对的人。
- 对第三方模型发送截图有隐私顾虑但又需要截图识别的人。

## 5. 产品定位

智能记账是一个本地优先、模型可配置、面向个人使用和开源探索的 AI 记账工具。

当前版本的定位不是“面向大众的免配置商业 App”，而是“愿意自己配置模型服务的用户可用的开源记账工具”。

## 6. 核心场景

### 6.1 自然语言记账

用户输入一句自然语言，例如“今天买咖啡 18 元，支付宝支付”，应用解析金额、分类、日期、备注和标签，并展示确认卡片。

### 6.2 盒马截图记账

用户上传盒马订单截图，应用调用视觉模型识别订单中的商品、数量、单位、金额和分类。保存后明细页展示为一条盒马父账单，点击后展开商品子项。

### 6.3 淘宝/天猫截图记账

用户上传淘宝/天猫订单截图，应用识别每个订单或商品，优先使用实付款金额，保存为多条独立账单。不强制识别数量和单位。

### 6.4 明细管理

用户查看本地账单明细，支持搜索、分类筛选、展开详情、单条删除和批量删除。

### 6.5 预算与洞察

用户在仪表盘查看月度支出、预算进度、分类结构、标签汇总、日历视图和智能洞察。盒马父账单在总额上只记一笔，在分类统计中按子项摊分。

### 6.6 模型配置

用户在设置页填写 API Key、接口地址和模型名称，并测试模型是否支持文字、JSON 和图片能力。

## 7. 功能范围

## 7.1 AI 记账输入

### 需求

- 支持自然语言输入。
- 支持图片上传。
- 输入文字时显示文字解析状态。
- 上传图片时显示截图识别状态。
- 解析完成后展示确认卡片。
- 保存前允许用户修改金额、日期、支付方式、分类和拆单项。

### 验收标准

- 输入文字时 loading 文案不得显示为截图识别。
- 上传图片时 loading 文案应明确表示正在识别截图。
- 解析结果必须先进入确认状态，不应直接静默入账。
- 支付方式为可选项，未选择时不强制显示。

## 7.2 图片识别

### 需求

- 支持通过视觉模型识别账单截图。
- 默认模型配置为 `mimo-v2.5`。
- 支持用户自定义模型接口。
- 支持本地 OCR 和规则解析作为回退。
- 展示识别来源：
  - 视觉模型识别
  - 本地 OCR 回退
  - 样本规则识别

### 验收标准

- 可在设置页测试图片能力。
- 视觉模型失败时，应尽量回退而不是直接阻断流程。
- 回退结果应在界面中体现可信度或来源差异。

## 7.3 盒马订单规则

### 需求

- 识别盒马订单后，保存为一条父账单。
- 父账单显示总金额、日期、分类、标签和识别说明。
- 父账单可展开查看商品子项。
- 商品子项应包含：
  - 商品名称
  - 金额
  - 分类
  - 数量和单位
  - 标签
- 盒马订单实际保存总额以商品小项合计为准。
- 不因模型返回的顶层总额与小项合计不一致而误报。
- 若商品缺少数量或单位，应提示需核对。

### 验收标准

- 明细首页只出现一条盒马父账单。
- 点击父账单可以看到所有识别商品。
- 商品金额准确时，不应因为模型顶层总额差异提示“总额不一致”。
- 分类统计应按商品子项摊分。
- 父账单总额在月度总支出中只计一次。

## 7.4 淘宝/天猫订单规则

### 需求

- 淘宝/天猫订单识别后按订单或商品分别记录。
- 优先使用“实付款”金额。
- 不要求识别数量和单位。
- 商品可按语义分类，例如服饰、饮料、其他等。

### 验收标准

- 淘宝/天猫结果保存后应生成多条独立账单。
- 不应像盒马一样保存为父账单。
- 不应因缺少数量单位提示需核对。

## 7.5 分类体系

### 默认分类

- 餐费
- 饮料
- 交通
- 娱乐
- 日用
- 服饰
- 数码
- 人情
- 医疗
- 交费
- 维修
- 其他

### 分类规则

- 咖啡、牛奶、酒水、饮品归入饮料。
- 生鲜、熟食、零食、水果、主食归入餐费。
- 洗护、清洁、纸品归入日用。
- 鞋服归入服饰。
- 检测、查重、线上服务归入其他。
- 水电燃气、物业、话费等归入交费。
- 修理、保养、配件安装等归入维修。

### 验收标准

- 所有识别结果的分类必须存在于当前用户分类列表。
- 如果模型返回不存在的分类，应映射到已有分类。
- 用户可在设置页新增或删除分类。

## 7.6 标签体系

### 需求

应用应自动提炼消费场景标签，例如：

- `#饮品补给`
- `#家庭餐食`
- `#日用补给`
- `#衣物鞋履`
- `#线上服务`
- `#盒马采购`
- `#网购订单`

### 验收标准

- 明细中可展示账目标签。
- 搜索应能匹配标签。
- 仪表盘分类页应展示标签汇总。

## 7.7 明细管理

### 需求

- 支持按关键词搜索。
- 支持按分类筛选。
- 支持展开查看详情。
- 支持单条删除。
- 支持管理模式。
- 支持全选当前筛选结果。
- 支持批量删除。
- 盒马父账单展开后展示子项。

### 验收标准

- 管理模式下点击账单用于选择，不展开详情。
- 批量删除只删除选中条目。
- 搜索应覆盖描述、详情、分类、金额、支付方式、标签和盒马子项。

## 7.8 仪表盘

### 需求

- 展示月度总支出。
- 展示预算使用比例。
- 展示日均支出。
- 展示本月笔数。
- 展示周趋势。
- 展示分类结构。
- 展示标签汇总。
- 展示日历视图。
- 展示智能洞察。

### 统计规则

- 月度总支出按父账单金额统计，避免重复计算。
- 分类统计按账单子项摊分。
- 盒马父账单的商品子项参与分类与标签统计。
- 没有子项的普通账单按自身分类统计。

### 验收标准

- 盒马父账单总额不得在总支出中重复计算。
- 分类统计应能体现盒马商品中饮料、餐费、日用等不同类别。

## 7.9 设置页

### 需求

- 支持配置 API Key。
- 支持配置接口地址。
- 支持配置模型名称。
- 支持模型能力测试。
- 支持配置月度预算。
- 支持管理分类。
- 支持清空数据并重置设置。

### 模型能力测试

测试项：

- 文字能力
- JSON 输出能力
- 图片理解能力

### 验收标准

- 设置页不应把某个模型写死为唯一选择。
- 应提示建议使用视觉模型。
- 使用文本模型时，应提示截图拆单能力可能不完整。

## 7.10 本地数据与兼容

### 本地存储

- `ab_transactions`
- `ab_settings`
- `ab_schema_version`

### 需求

- 新用户首次安装账本为空。
- 不写入测试 seed 数据。
- 老用户升级保留真实账单。
- 老用户升级保留设置、API Key、预算和分类。
- 旧版本测试账单应自动清理。

### 验收标准

- 清空 LocalStorage 后进入应用，明细为空。
- 已有真实账单升级后仍存在。
- `seed-001` 到 `seed-009` 测试账单不应保留。

## 10. AI 与回退策略

### 优先级

1. 视觉模型识别
2. Android 本地 OCR
3. 已知样本规则
4. 普通文本规则回退

### 要求

- 视觉模型返回 JSON。
- 应兼容模型返回 `content` 或 `reasoning_content`。
- 应兼容 JSON 被包裹在代码块中的情况。
- 识别失败时尽量回退。
- 回退结果应提示用户核对。

## 11. 隐私边界

### 本地保存

- 账单
- 设置
- API Key
- 分类
- 预算

### 可能发送到模型服务

- 用户输入文本
- 用户上传截图
- 近期账单摘要
- 统计结果
- 模型能力测试请求

### 不应发生

- 作者服务器收集账单。
- 源码中提交 API Key。
- 提交测试截图。
- 提交真实账单截图。

## 12. 异常处理

### 模型失败

- 显示失败或回退结果。
- 不直接保存错误账单。
- 允许用户手动编辑。

### 图片能力不足

- 设置页模型测试应提示图片能力可能不支持。
- 截图识别失败时应提示用户核对或更换模型。

### 金额不一致

- 盒马多商品订单以子项合计为准。
- 非盒马订单如模型总额与拆单合计不一致，应提示需核对。

### 数量缺失

- 盒马商品缺少数量或单位时提示需核对。
- 淘宝/天猫不因数量缺失提示。

## 13. 验收标准

### 基础验收

- `npm run build` 通过。
- `npm run lint` 通过。
- `npm run android:sync` 通过。
- Android debug APK 构建通过。

### 新用户验收

- 清空 LocalStorage 后进入应用，明细为空。
- 默认分类正确。
- 默认模型为 `mimo-v2.5`。

### 老用户验收

- 已有真实账单保留。
- 设置保留。
- API Key 保留。
- 预算保留。
- 旧测试账单清理。

### AI 记账验收

- 文字输入显示文字解析 loading。
- 图片上传显示截图识别 loading。
- 解析结果进入确认卡。
- 支付方式可为空。

### 盒马验收

- 保存为一条父账单。
- 可展开商品子项。
- 商品子项有金额、分类、数量和单位。
- 分类统计按子项摊分。
- 不因模型顶层总额差异误报。

### 淘宝/天猫验收

- 分别保存订单或商品。
- 优先使用实付款。
- 不要求数量单位。

### 明细验收

- 搜索可匹配子项和标签。
- 管理模式可批量删除。
- 展开详情展示识别来源和需核对提示。

### 设置验收

- 可配置 API Key、接口地址、模型名称。
- 可测试文字、JSON、图片能力。
- 可管理分类和预算。

## 14. 当前限制

- 识别质量取决于用户配置的模型能力。
- 当前没有云同步和账号体系。
- 当前没有正式应用商店上架流程。
- 当前没有完整自动化测试覆盖。
- 当前 APK 为 debug 包。
- LocalStorage 数据可能因卸载、清理数据或 WebView 异常丢失。
