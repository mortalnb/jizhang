# 智能记账 PRD

## 1. 版本与定位

- 产品：智能记账
- 当前候选版本：`v1.5.0-rc.2`
- 形态：Android / Web，本地优先，GitHub APK 分发
- 发布状态：独立 RC 分支在线测试；用户验收前不迁移 `main`
- 模型：文字与视觉 `mimo-v2.5`，语音固定 `mimo-v2.5-asr`

本版本解决三类核心问题：一段输入包含多笔消费时不再聚合；超市与电商按真实账单性质折叠；应用直接采集麦克风音频并调用 MiMo ASR。同时新增默认关闭的云端账本快照。

## 2. 数据原则

1. 本地账本始终是用户当前操作的主账本。
2. AI 只生成草稿，不自动入账。
3. 一次确认中的多笔交易只进行一次本地提交，要么全部成功，要么不写入。
4. 不同日期、不同结账事件、不同订单号或独立消费必须是不同顶层交易。
5. 同一次结账/同一订单的商品是子项，不是独立交易。
6. 云同步必须主动开启；云端恢复必须再次确认。
7. 自填 API Key、会话 token、密码和设备凭据不得进入备份或云快照。

## 3. 统一解析模型

模型最外层返回：

```text
ParsedBatch
  transactions[]
    amount
    category
    description
    detail
    date
    tag（0 或 1 个场景标签）
    merchant / orderId
    grouping: folded | separate
    splitItems[]
```

`transactions` 是真实发生的独立支出；`splitItems` 是同一付款内部的商品明细。父级 `amount` 表示实际支付，商品合计可以因优惠、运费或漏识别与父级不同。

### 验收

- “8 月 1 日咖啡 18 元；8 月 2 日地铁 3 元”生成两张卡，各自保留日期。
- 批量确认只调用一次 `saveTransactions`。
- 保存后立即重新读取账本不会出现“校验和不匹配”。
- 用户可以删除、编辑任一草稿后再统一保存。

## 4. 账单分组策略

### 超市

盒马、沃尔玛、山姆及其他明确属于一次结账的小票：

- 顶层只保存一笔；
- 商品进入 `splitItems`，明细页可展开；
- 尽量保留数量和单位；
- 父级使用优惠后的实付金额；
- 分类统计使用子项，月度总支出只计算父级一次。

### 淘宝/天猫

- 同一订单中的多个商品允许折叠；
- 订单列表里的多个订单保持多笔；
- 不同日期或多次实付款必须拆分；
- 优先使用每个订单的实付款；
- 不强制数量单位。

### 人工覆盖

- “商品展开为多笔”把所有子项转为顶层交易；
- “手动合并为一笔”把多笔转为一个父级；
- 若原交易跨日期，合并前必须警告使用第一笔日期。

## 5. 应用内语音

### 流程

1. 用户点击麦克风并授权录音。
2. 应用采集单声道音频，停止或达到 60 秒时编码为 16 kHz PCM WAV。
3. 自填模式直接调用 MiMo；云端模式调用 `/api/model/transcribe-audio`。
4. 模型固定为 `mimo-v2.5-asr`，语言提示为中文。
5. 转写文字回填输入框，允许编辑。
6. 用户再点击解析，进入 `ParsedBatch` 确认流程。

### 验收

- 不调用输入法语音能力。
- 未授权麦克风、录音过短、超过大小限制、网络失败和空转写都有明确错误。
- 音频 Base64 不超过 MiMo 10 MB 限制。
- 服务端请求体与授权头在日志中被隐藏，不保存录音。
- 语音转写完成后绝不直接写账本。

## 6. 本地完整性与恢复

- 存储 schema 为 5；新账本不再保存支付方式。
- checksum 必须先进行 JSON 等价规范化，避免 `undefined` 在持久化时消失导致误报。
- schema 3/4 升级时先保留原始交易和设置，再生成 schema 5 manifest；金额、日期、描述和分类保持不变。
- 历史空数组/多值标签只兼容为一个场景标签；明确品牌可补为商户索引。不得用旧备份静默覆盖较新的本机或云端账本。
- schema 5 的 checksum 真正不匹配时仍进入只读恢复模式。
- 手动和自动备份使用 backup version 2；可结构化迁移受旧校验缺陷影响的 version 1 备份。
- 每次写入前保存恢复快照。

## 7. 云同步

### 范围

同步：交易、子项、识别元数据、分类、预算。
不同步：API Key、模型地址、云端 token、密码、设备标识。

### 协议

- `GET /api/ledger-snapshot`：读取当前账号快照。
- `PUT /api/ledger-snapshot`：提交 payload、checksum 和 `expectedRevision`。
- 服务端重新验证结构和 checksum。
- 第一次上传 revision 为 1；后续乐观递增。
- revision 冲突返回 409，客户端暂停自动覆盖。

### 客户端行为

- 默认 `cloudSyncEnabled=false`。
- 开启时：云端为空则上传；内容一致则建立版本；内容不同则进入 conflict。
- 本地写入后延迟自动上传。
- 冲突时优先“合并云端与本机”：同 ID 保留本机，只补云端独有记录，再基于云端当前 revision 上传合并结果。
- “本机覆盖云端”和“从云端覆盖本机”是次级危险操作，必须确认；覆盖本机前先创建恢复快照。
- 退出账号会关闭同步，但不会静默删除云端数据。

## 8. 服务端要求

- Fastify body limit 足以容纳 10 MB Base64 音频。
- 模型并发槽：文字 2、图片 1、语音 1。
- `mimo-v2.5-asr` 必须在授权模型列表中。
- 用量记录包含接口、模型、成功、耗时和语音秒数，不保存请求内容。
- 模型 JSON 必须经过 Zod 合同验证后才返回客户端。
- `/api/version` 返回版本、提交 SHA 和能力列表。
- 镜像以 Git SHA 标签构建；数据库迁移显式执行。

## 9. 页面要求

### 记一笔

- 文字框、应用内语音、图片入口；
- 语音计时和 60 秒说明；
- 多笔确认卡，每笔可改金额、日期、描述和分类；
- 商品子项可编辑金额、名称、数量和分类；
- 展示实付与明细合计差异；
- 展开/合并人工覆盖按钮；
- 入账按钮显示顶层交易数量并防重复提交；
- 保存后留在当前页、清空并聚焦输入框，只有点击“查看刚入账明细”才跳转。

### 设置

- 自填模型与云端账号；
- 文字/JSON/图片/语音能力提示；
- 云同步开关、状态、revision、最近时间、冲突说明；
- 本机覆盖云端、云端恢复本机；
- 本地导出/导入、分类和预算。

### 明细与仪表盘

- 折叠父级只占一行；
- 子项可展开和编辑；
- 总支出按父级；分类按实付金额比例分摊到子项，优惠不能造成分类合计高于总支出；
- 标签只允许一个场景值；覆盖率低于 40% 时不进入仪表盘或模型洞察；
- 商户只用于明细显示、搜索和筛选，不进入统计或模型结论；
- 批量文字录入可通过共享 `batchId` 追踪，但列表仍显示独立交易。

## 11. 已知边界

- 当前仍为 debug APK，未走应用商店签名与审核。
- 云快照是服务端可读的 HTTPS 备份，不是端到端加密。
- 当前账号仍是一账号一设备绑定，不是完整多端合并系统。
- 模型可能误判订单边界或漏商品，所以保留人工确认与覆盖。
- WebView LocalStorage 仍可能因卸载/清数据丢失；应使用导出或可选云同步。
